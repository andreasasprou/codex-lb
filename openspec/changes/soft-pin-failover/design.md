## Decisions

1. `_http_bridge_request_rebind_safe(payload, headers, request_state, durable_lookup)` returns `False` on any missing or malformed proof. It requires no `previous_response_id`, no `conversation`, no `x-codex-turn-state` header, no input file id, a full-resend shape, strict account-neutral replay validation, an exact match against the stored input-prefix count and fingerprint, and shared causal closure.
2. The hard-key and fallback-disabled preferred-account requirement is softened only when `rebind_safe` is true. Previous-response and file-owner requirements remain hard.
3. `_create_http_bridge_session` makes one preferred selection first. If it returns no account for a code other than `account_stream_cap` or `account_response_create_cap`, it makes one unpinned selection with empty affinity only when `rebind_safe` is true. If refresh or WebSocket connection attempts later force an account switch, that selection also uses empty affinity.
4. Every rebind-safe connection to a non-preferred account removes all HTTP bridge affinity headers. The durable canonical row remains the session key and is claimed through the existing transaction. Account-change claims clear stale aliases but preserve the stored input count and fingerprint until completed response registration replaces them.
5. Existing WebSocket and non-bridge selection callers retain their current call shape and defaults.
